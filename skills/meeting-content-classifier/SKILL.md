# 会议内容分类器 Skill

本技能是「会议决策行动项提取工具」业务整体流程中 **M2 内容识别** 环节的子模块——**内容分类**。它把一个「小问题」独立封装：给定一句会议字幕，判定它到底是「正式决策」「待执行行动项」还是「普通讨论」。

> 设计起点来自项目五条业务铁律，尤其 **铁律1「不把讨论意见当作正式决定」**：本技能在分类时会优先识别讨论特征词，避免把"我觉得/大家怎么看"误判成决策。

---

## 一、输入格式

接受 **单条** 字幕句子的 JSON：

| 字段       | 类型     | 必填 | 说明                                        |
|------------|----------|------|---------------------------------------------|
| `text`     | string   | 是   | 字幕句子原文                                 |
| `position` | string   | 否   | 原始字幕位置/时间戳，用于溯源（铁律5）       |
| `speaker`  | string   | 否   | 发言人，仅回显，不参与判定（铁律4：不替他人承诺） |

示例：

```json
{
  "text": "经过讨论，我们决定下周三正式发布 v2.0 版本",
  "position": "字幕第 42 行 / 00:15:20",
  "speaker": "王经理"
}
```

---

## 二、输出格式

始终返回结构化 JSON：

| 字段                       | 类型             | 说明                                                                 |
|----------------------------|------------------|----------------------------------------------------------------------|
| `ok`                       | bool             | 是否成功分类（失败路径为 false）                                     |
| `content_type`             | string\|null     | `决策` / `行动项` / `普通讨论`；失败时为 null                       |
| `confidence`               | string\|null     | `high` / `medium` / `low`；失败时为 null                            |
| `matched_keywords`         | string[]         | 命中的特征词列表                                                     |
| `needs_human_confirmation` | bool             | 是否需要人工确认（信息不全/不可溯源时为 true）                       |
| `position`                 | string\|null     | 回显原始位置                                                         |
| `speaker`                  | string\|null     | 回显发言人                                                           |
| `reason`                   | string           | 判定理由（含触发的铁律说明）                                         |
| `error_code`               | string           | 仅失败路径出现，如 `INVALID_INPUT`                                   |
| `error_message`            | string           | 仅失败路径出现                                                       |
| `input_text`               | string\|null     | 回显输入文本，便于结果对照                                           |

---

## 三、分类规则

### 3.1 三类特征词表

- **决策类**（表示已形成正式结论/共识/授权）：
  `决定` `确定` `拍板` `通过` `批准` `决议` `一致认为` `最终决定` `最终确定` `统一意见` `达成共识` `会议决定` `原则上通过` `审议通过` `同意立项` `确认采用`

- **行动项类**（表示存在待执行任务与责任指派）：
  `负责` `跟进` `落实` `督办` `安排` `推进` `交付` `完成` `待办` `TODO` `牵头` `执行` `指派` `认领` `归口`

- **讨论类**（表示尚在商讨/征询/表达个人看法，未形成结论）：
  `我觉得` `我认为` `可能` `是否` `建议` `大家怎么看` `讨论一下` `再想想` `待商榷` `倾向于` `可以考虑` `怎么样` `你们觉得` `有没有可能` `或许` `好像`

### 3.2 强决策词

下列词视为「强决策信号」，一旦出现即压制讨论特征：
`决定` `确定` `拍板` `通过` `批准` `决议` `最终决定` `达成共识` `会议决定`

### 3.3 判定优先级

```
1. 若命中「讨论特征词」且未出现「强决策词」 → 普通讨论（铁律1：不把讨论当决定）
2. 否则若命中「决策特征词」               → 决策
3. 否则若命中「行动项特征词」             → 行动项
4. 否则                                  → 普通讨论（降级）+ 低置信 + 需人工确认
```

### 3.4 人工确认触发条件（`needs_human_confirmation=true`）

- 判为普通讨论（讨论中可能隐含任务倾向，需人工复核是否升级）；
- 未命中任何特征词（无法自动判定）；
- `position` 缺失（不可追溯，违反铁律5）；
- 输入无效（失败路径）。

---

## 四、边界与失败处理

| 场景 | 输入特征 | 期望行为 | 对应铁律 |
|------|----------|----------|----------|
| 正常-决策 | 含强决策词 + 有 position | 决策/high/无需确认 | — |
| 正常-行动项 | 含行动项词 + 有 position | 行动项/high/无需确认 | — |
| 边界-讨论倾向 | 命中讨论词、无强决策词 | 普通讨论/low/需确认 | 铁律1 不把讨论当决定 |
| 边界-无特征词 | 无任何特征词 | 普通讨论/low/需确认 | 铁律3 信息不全须人工确认 |
| 边界-不可追溯 | position 缺失 | 类型照常判，但需人工确认 | 铁律5 任务须可追溯 |
| 失败-无效输入 | text 为空/非字符串/缺失 | `ok=false` + `INVALID_INPUT` | 铁律2 不臆测补全 |

> 本环节**只做分类，不做实体抽取与补全**：不产出责任人、不补全截止时间（这些由下游 M2 实体抽取 / M3 合规校验负责），从源头杜绝虚构。

## 五、测试结果（3 条核心 + 2 条补充）

> 以下均为真实运行 `scripts/classify.py` 的输出，覆盖**正常流程 / 边界场景 / 失败路径**。

### 测试 1 ｜ 正常流程·决策句（T1）

**输入**
```json
{"text":"经过讨论，我们决定下周三正式发布 v2.0 版本","position":"字幕第 42 行 / 00:15:20","speaker":"王经理"}
```
**运行命令**（用 `--file` 指向单条 JSON 样本，脚本自动识别单对象/数组）
```powershell
python scripts/classify.py --file tests/single_example.json
```
**输出**
```json
{
  "ok": true,
  "content_type": "决策",
  "confidence": "high",
  "matched_keywords": ["决定"],
  "needs_human_confirmation": false,
  "position": "字幕第 42 行 / 00:15:20",
  "speaker": "王经理",
  "reason": "命中决策类特征词，判定为正式决策",
  "input_text": "经过讨论，我们决定下周三正式发布 v2.0 版本"
}
```
**结论**：命中强决策词「决定」→ 决策/high/无需确认。✅ 正常流程通过。

---

### 测试 2 ｜ 边界场景·讨论句（T3）——体现「不把讨论当决定」

**输入**
```json
{"text":"我觉得这个方案可能风险有点大，大家怎么看？是否需要再评估一下","position":"字幕第 73 行 / 00:21:40","speaker":"赵工"}
```
**输出**
```json
{
  "ok": true,
  "content_type": "普通讨论",
  "confidence": "low",
  "matched_keywords": ["我觉得", "可能", "是否", "大家怎么看"],
  "needs_human_confirmation": true,
  "position": "字幕第 73 行 / 00:21:40",
  "speaker": "赵工",
  "reason": "命中讨论特征词且未出现强决策结论词，按铁律1「不把讨论当决定」判定为普通讨论",
  "input_text": "我觉得这个方案可能风险有点大，大家怎么看？是否需要再评估一下"
}
```
**结论**：句中虽含「可能/是否」等模糊表达，但无强决策词；按铁律1判为普通讨论/low/需人工确认。✅ 边界场景通过，避免了把讨论误判为决策。

---

### 测试 3 ｜ 失败路径·空文本（T4）

**输入**
```json
{"text":"","position":"字幕第 90 行 / 00:24:10","speaker":"未知"}
```
**输出**
```json
{
  "ok": false,
  "error_code": "INVALID_INPUT",
  "error_message": "text 字段缺失或非字符串，无法进行内容分类",
  "content_type": null,
  "confidence": null,
  "matched_keywords": [],
  "needs_human_confirmation": true,
  "position": "字幕第 90 行 / 00:24:10",
  "speaker": "未知",
  "reason": "输入无效：缺少有效文本，按铁律不臆测分类结果",
  "input_text": ""
}
```
**结论**：text 为空 → 返回结构化错误 `INVALID_INPUT`，不臆测补全类型。✅ 失败路径通过。

---

### 补充测试 4 ｜ 正常流程·行动项句（T2）

**输入**：`张三负责跟进这个客户的交付，李四推进接口联调`
**输出**：`content_type=行动项` / `confidence=high` / `matched_keywords=["负责","跟进","推进","交付"]` / `needs_human_confirmation=false` ✅

### 补充测试 5 ｜ 边界场景·无特征词且缺 position（T5）

**输入**：`{"text":"那这个事情先这样吧","position":null,"speaker":null}`
**输出**：`content_type=普通讨论` / `confidence=low` / `matched_keywords=[]` / `needs_human_confirmation=true` / `reason="未命中任何特征词…；原始字幕位置缺失，不可追溯，须人工确认"` ✅（同时触发铁律3与铁律5）

## 六、如何运行

### 6.1 CLI 直接传一句话

```powershell
python scripts/classify.py "我们决定下周三发布 v2.0"
```

### 6.2 单条 JSON 文件模式

推荐用 `--file` 指向单条 JSON（脚本自动识别单对象/数组，单条时直接返回对象而非数组）：

```powershell
python scripts/classify.py --file tests/single_example.json
```

> 脚本也支持 `--json` 从 stdin 读单条 JSON。bash 下可用 `echo '{"text":"..."}' | python scripts/classify.py --json`；但 **Windows PowerShell 把字符串管道传给原生程序时 stdin 不可靠，输出会被流对象化吞掉，强烈建议改用 `--file`**。

### 6.3 批量跑测试样本

```powershell
$env:PYTHONIOENCODING="utf-8"
python scripts/classify.py --file tests/sample_inputs.json
```

> Windows 下若中文乱码，先执行 `$env:PYTHONIOENCODING="utf-8"`。

## 七、范围与局限

- **本技能仅做分类**：不抽取责任人/截止时间（由 M2 实体抽取负责），不输出 M4 的 6 字段全量结构。
- **基于关键词规则**：未接入语义模型，对含蓄表达（如无特征词的隐性决策）会降级为「普通讨论 + 需人工确认」，宁可漏判也不误判（服从铁律1）。
- **单句处理**：不做跨句上下文推理，复杂多句决议建议上游 M1 先做句子切分。
- **可扩展点**：特征词表集中于 `scripts/classify.py` 顶部，可按业务沉淀持续扩充。
